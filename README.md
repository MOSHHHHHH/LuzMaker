# לו״ז מייקר

אפליקציית קוד פתוח בעברית ליצירת לוחות זמנים אישיים לאוטובוסים בישראל, ללא שרת בתשלום.

## שימוש
האתר: https://moshhhhhh.github.io/LuzMaker/

- צרו קבוצת קווים, בחרו מסלולים ותחנות ושמרו את הקבוצה בדפדפן.
- בחרו תאריכים ידנית (עד חמישה) או הפעילו השוואה חכמה לכל הימים הזמינים.
- ימים עם לוחות נסיעה זהים יקובצו יחד; ניתן לתת כינוי לכל לוח.
- ייצאו CSV או הורידו PDF שנוצר ישירות ב־JavaScript, לכל לוח בנפרד או לכל הלוחות יחד.
- ליד קו שנוסף לקבוצה אפשר לבחור כמה קווים וחלופות נוספים מאותו מספר תחנה.
- במזהה השינויים אפשר לחפש לפי שם או מספר תחנה ולצרף תחנות בטווח 300 מטר בקו אווירי.

**הבהרה חשובה:** אלה זמני נסיעה *מתוכננים*, לא נתוני זמן אמת. יש לוודא נסיעות אצל המפעיל.

## הגדרת היום
היום התחבורתי מתחיל ב-**03:00** ומסתיים ב-**02:59:59 למחרת**.

- נסיעה בשבת בשעה 02:30 לפנות בוקר שייכת ללוח של יום שישי.
- GTFS יכול לכלול שעות כמו `25:30:00`; הן נשמרות בהתאם ליום השירות המקורי ומתורגמות ליום התחבורתי הנכון.
- החיתוך מיושם בעיבוד, במיון ובהפקת הלוחות.

## מקור הנתונים
הקובץ הרשמי: https://gtfs.mot.gov.il/gtfsfiles/israel-public-transportation.zip

הסקריפט `scripts/build_gtfs.py` קורא את `routes.txt`, `trips.txt`, `stop_times.txt`, `stops.txt`, `calendar.txt` ו-`calendar_dates.txt`, ומייצר קובצי JSON קטנים לפי מספר קו.

הפורמט המעובד משתמש במסכת ביטים של 14 יום ובקיבוץ נסיעות לפי שירות ותחנה, כדי להימנע מכפילות מיותרת של תאריכים.

## פרסום אוטומטי
ה-workflow `.github/workflows/gtfs-pages.yml` מבצע:
1. בדיקות יחידה לתאריך, לשעות חצות ולחריגי לוח.
2. בדיקת תחביר של JavaScript.
3. הורדת GTFS רשמי ועיבודו.
4. אימות נתונים ופרסום דרך GitHub Pages.

העדכון מתוכנן מדי יום בשעה 05:35 UTC, וניתן להפעילו ידנית. קבצי ה-ZIP וה-JSON לא נשמרים בהיסטוריית Git; תוצרי הפרסום נארזים כ-GitHub Pages artifact.

**כדי לאפשר פרסום:** בהגדרות המאגר, תחת Settings → Pages → Build and deployment → Source, בחרו GitHub Actions. אם כבר מוגדר כך, אין צורך לשנות דבר.

## בדיקות מקומיות
```bash
python -m unittest discover -s tests -v
python scripts/build_gtfs.py --zip /path/to/israel-public-transportation.zip --output _site
cp index.html changes.html favicon.svg logo.svg aliases.js packing.js pdf.js _site/
cp scripts/shes.js _site/
cp -R assets _site/
python -m http.server 8000 -d _site
```

## פייבאיקונים של מפעילי תחבורה
תמונות המפעילים הן **פייבאיקונים של אתר המפעיל בלבד**, כפי שהוא מזוהה ב-`agency_url` של GTFS. בעת הבנייה היומית מחפשים אייקון באתר עצמו (כולל Apple Touch Icon וסוגי קבצים נפוצים). אם האיתור הישיר נכשל, מנסים את שירות Google S2 הלא-רשמי בתור **מתווך לאייקון של אותו אתר בלבד**, ולא כמקור ללוגואים אחרים. השירות אינו מתועד רשמית ועלול להחזיר אייקון גנרי או להפסיק לפעול; תגובה לא תקינה או אייקון קטן נדחים.

רק קובצי תמונה מקומיים מסוג PNG, ICO, WebP או JPEG נכללים באתר. קובצי SVG חיצוניים אינם מפורסמים ישירות מטעמי אבטחה. אין בקשות חיצוניות מדפדפן המשתמש ואין צורך בהגדרות. בהיעדר תמונה מוצג שם המפעיל בלבד.
דוח בנייה ניתן למצוא ב-`data/operator-icons-report.json` באתר ובלוגי GitHub Actions; הוא מציג את המפעילים שהצליחו ואת סיבת הכישלון בקצרה.
כתובות גיבוי שאומתו ידנית נשמרות ב-`data/operator-website-fallbacks.json` לפי `agency_id`. בכל ריצה מנסים קודם את `agency_url` מתוך GTFS (ישירות ואז Google), ורק אם לא התקבלה תמונה ממשיכים לכתובות הגיבוי באותו סדר. הדוח מציין גם את `selected_website` ואת `website_source` (`gtfs` או `fallback`). אין שיוך לאתר של חברה אחרת בלי אימות לזהות המפעיל.

פייבאיקונים עשויים להיות סימני מסחר של המפעילים, והצגתם אינה מעידה על חסות או שיתוף פעולה.

## מצב הפרויקט
גרסת בטא. שמירת קבוצות מקומית בלבד; אין סנכרון בין מכשירים. יצירת PDF מתבצעת ישירות ב־JavaScript, עם גופן מוטמע ופריסה מדודה שאינה תלויה בחלון ההדפסה.


## שמות לוחות וייצוא PDF (נובמבר 2026)

- שם ברירת המחדל נקבע לפי מועד יהודי בולט החל בתאריכי השירות בישראל, אחריו יום השבוע, ואחריו תאריך לפי העדפת תצוגת הלוח. תאריכים חולקים שם חג רק אם כולם מתאימים לאותו מועד; זהו תיאור קלנדרי **ולא אישור** שהמפעיל הפעיל מתכונת שירות מיוחדת.
- בעת יצירת ברירות מחדל מצורפות סיומות מספריות למניעת שמות כפולים; הזנת שם כפול באופן ידני נחסמת.
- ה־PDF משתמש בארבעה טורים כרונולוגיים, מקרא משותף בכל עמוד ואריזת לוחות שונים לאותו A4. הגופן המוטמע ומדידות הרוחב והגובה ב־`pdf.js` קובעים את הפריסה, עם BiDi של Unicode לעברית, מספרים ואנגלית.
- מנוע `packing.js` מחפש מספר עמודים מינימלי במודל המדוד עבור עד 16 מקטעי סיום, במגבלת חיפוש. במקרים גדולים הוא משתמש ב־best-fit decreasing. חלקים של אותו לוח נשמרים בסדרם, ואין כיווץ של כתב השורות מתחת ל־9pt.
- הספריות והגופנים נכללים באתר ונטענים רק בעת יצוא PDF. טקסט ה־PDF הוא וקטורי ובעל מיפוי Unicode. אין פנייה לשירות המרה חיצוני.
- הסמליל `logo.svg` הוא גרסה וקטורית קומפקטית של לוח זמנים ושעון ומופיע גם בכותרות ההדפסה.
- מיפוי המועדים נשען על תאריכים בלוח העברי. לדיון בדפוסי נסיעות מיוחדים ראו את נספח י״ג של משרד התחבורה: https://www.gov.il/BlobFolder/guide/agreements_for_operating_service_lines_in_public_transportation/he/GalileeTender.pdf. נספח זה אינו משמש מקור להנחה של נסיעות פעילות או זמני נסיעה.


## עדכון מועדים מיוחדים

הסיווג משתמש בשני סוגי תאריך לפי המועד: מועדי ישראל, צומות ומועדים ממלכתיים מחושבים לפי הלוח העברי וכללי הדחייה; מועדים אזרחיים בעלי תאריך קבוע (למשל 1 בינואר ו־25 בדצמבר) מחושבים לפי הלוח הגרגוריאני.

בזמן בניית אתר GitHub Pages מתבצעת פנייה אחת ל־[Hebcal](https://www.hebcal.com/home/developer-apis) לטווח תאריכי ה־GTFS, וסיווג המועדים נשמר מקומית ב־`data/holidays.json`. השירות מספק נתונים ברישיון CC BY 4.0, בקרדיט Hebcal.com. דפדפן המשתמש אינו פונה אל Hebcal. אם השירות אינו זמין בזמן הבנייה, נשמר JSON ריק והדפדפן משתמש בכללי חישוב מקומיים ב־`aliases.js`, כולל דחיית צומות וימי זיכרון/עצמאות.

הזיהוי הוא קלנדרי בלבד. אין בו הנחה לגבי מספר נסיעות בימי חג או סיווג כל קו לפי דת ואזור; מקור זמני הנסיעות נשאר GTFS. חופשות בתי ספר, בין הזמנים והודעות מיוחדות על בחירות אינן ניתנות לזיהוי מדויק בלי מקורות נוספים, ולכן לא סומנו אוטומטית.


### בדיקות פריסת PDF

בדיקות `tests/packing-smoke.cjs` בודקות את אריזת המקטעים. `tests/pdf-print-smoke.cjs` מייצרת PDF ישירות ב־JS, ו־`tests/check_generated_pdf.py` בודקת אותו באמצעות MuPDF: גבולות A4, גופנים מוטמעים, סדר טורים וחלקים, מספר עמודים, BiDi ושימור כל היציאות. בדיקות אלה חוסמות את בדיקת הענף לפני מיזוג. בדיקת הייצוא בדפדפן מוודאת גם הורדה ממשית והתאוששות מכשל בטעינת גופן.


### לוח משותף עם חג אחד או כמה חגים

כשקבוצת תאריכים חולקת בדיוק את אותן נסיעות GTFS, אין יוצרים לוחות כפולים רק בגלל חג. שם ברירת המחדל משלב את סוג היום הרגיל עם שמות החגים הייחודיים, למשל `אמצע שבוע (כולל ערב ראש השנה ו־סיגד)`. אם רק חגים מופיעים בלוח, מוצג `מועדים מיוחדים (כולל ...)`. שם ארוך במיוחד מתקצר כדי לעמוד בגבול 70 תווים. שמות שהמשתמש הזין ידנית אינם משתנים אוטומטית, ולוחות בעלי שם זהה נחסמים בעת יצירה.

ראו גם [תיעוד מזהה השינויים בתחנות](docs/station-changes.md), כולל מגבלות הארכיון ושחזור מצב.

פרטי אינדקס התחנות, בחירה מרובה ו־PDF: [תיעוד התוספות](docs/station-tools-and-pdf.md).
